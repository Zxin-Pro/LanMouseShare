## 2. 兼容性审查

### 2.2 Win10+ 专属 API 与它的 Win7 回退（逐一核对）

**这是整个项目最容易在 Win7 上炸掉的地方**，所以逐个 API 核对回退路径：

| API | 最低系统 | 回退处理 | 是否安全 |
| --- | --- | --- | --- |
| `user32!SetProcessDpiAwarenessContext` | Win10 1703 | `catch (EntryPointNotFoundException)` → 落到下一级 | 安全 |
| `shcore!SetProcessDpiAwareness` | Win8.1 | `catch (DllNotFoundException)` → 落到 Win7 级（**Win7 上 shcore.dll 不存在，这正是走这条路的场景**） | 安全 |
| `user32!SetProcessDPIAware` | Vista | 最底层，Win7 一定能用 | 安全 |
| `user32!AreDpiAwarenessContextsEqual` | Win10 1703 | 只在「回读级别」时调用，失败被外层 try 吞掉 | 安全 |

对应代码 `src\LanMouseShare.App\Core\Interop\DpiAwareness.cs:103-180`，三级回退链自带可读的降级说明，运行期写进日志（例如 `shcore.dll 不存在（系统低于 Windows 8.1，这正是 Win7 的情况）`）。

**一个非直觉的事实**：光靠运行时调用，本程序其实**拿不到 PerMonitorV2**——实测日志是
`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2) 返回 false，Win32=5(ERROR_ACCESS_DENIED：感知级别已被提前锁定)`。
原因是 `app.manifest` 在进程启动时已把感知级别锁死，运行时 API **只能降级不能升级**。
所以三级回退链的真正职责是「万一 manifest 没生效时的兜底」，主路径仍然是 manifest。

### 2.3 C# 语法约束（本机工具链的现实限制）

本机没装 net48 目标包，构建走 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe`，
它自带的 csc **只支持到 C# 5**。以下语法在本项目一律禁用，已全量扫描确认无残留：

| 禁用语法 | 后果 | 替代写法 |
| --- | --- | --- |
| 内联 out 变量声明 `out string x` | CS1513 等一串连锁错误 | 先声明 `string x;` 再 `M(out x)` |
| 字符串插值 `$"..."` | 编译不过 | `"a" + b` |
| 空条件运算符 `?.` | 编译不过 | 显式判空 |
| 表达式体成员 `=>` | 编译不过 | 写完整方法体 |
| `nameof` | 编译不过 | 写字符串字面量 |
| 弃元 `out _` | CS1510「ref 或 out 参数必须是可赋值的变量」 | `string ignored; Load(out ignored)` |
| `??=` | 编译不过 | 显式赋值 |

> 历史事故：`src\LanMouseShare.App\Core\Sharing\HostController.cs` 曾因一行
> `if (!_hooks.InstallKeyboardHook(out string keyError))` 报出 CS1513 / CS1002 / CS1520 / CS1031 /
> CS1519 / CS0116 / CS1518 / CS1022 共 8 类错误，报错行号还指向文件末尾，看起来像括号不配对。

**另一条与兼容性同等重要的约定**：所有含非 ASCII 字符的源文件必须存成 **UTF-8 带 BOM**。
csc 遇到无 BOM 文件会按系统 ANSI 码页解码，中文字符串字面量会变成乱码写进程序。
项目用 `tools\ensure-bom.ps1` 每次构建前统一补齐（本次全量扫描 48 个文件）。

## 3. 线程安全审查

### 3.1 同步原语分布（实测统计）

| 文件 | `lock` 次数 | 保护的共享状态 |
| --- | --- | --- |
| `Core\Net\PeerConnection.cs` | 5 | 连接状态机、`_lastReceivedMs`、待发队列 |
| `Core\Net\FramePump.cs` | 4 | 发送队列、四个计数器 |
| `Core\Diagnostics\Log.cs` | 3 | 日志文件句柄、滚动索引 |
| `Core\Sharing\ClientController.cs` | 3 | 按下按键/按钮集合 |
| `Core\Sharing\HostController.cs` | 2 | 主机侧坐标基准与位置状态 |
| `Core\Net\TcpTransport.cs` | 1 | 套接字引用 |
| `Core\Diagnostics\NetworkLoopbackTest.cs` | 3 | 断言计数、收帧记录 |

另有 2 处 `volatile bool _running`（`Core\Net\FramePump.cs:35`、`Core\Net\TcpTransport.cs:28`）作跨线程停止标志——
这类「一个线程写、另一个线程读」的布尔量用 `volatile` 比加锁更轻，也不会阻塞发送线程。

### 3.2 线程边界：钩子回调绝不进 UI 线程

```
UI 线程（WPF）
  ↑ Dispatcher.BeginInvoke（只投递字符串/枚举）
主机钩子回调线程（WH_MOUSE_LL / WH_KEYBOARD_LL）
  ↓ Post(Frame) 进无锁队列
发送线程（FramePump，ThreadPriority.AboveNormal）
  ↓ 阻塞写
TCP
  ↓
接收线程（TcpTransport，专用后台线程阻塞读）
  ↓ 事件
UI 线程（同上，BeginInvoke）
```

**为什么钩子回调里不许做重活**：Windows 低级钩子回调有 **300 毫秒预算**，超时会被系统**静默摘钩**——
不报错、不返回失败，只是钩子从此不再被调用，表现为「程序看着好好的，但鼠标不过去了」。
所以回调里只做三件事：判断注入标记、算坐标、塞进队列。

### 3.3 关闭竞态

关闭路径是审查重点，因为**半关闭状态会让光标永远留在副机上**：

- `PeerConnection.OnTransportState` 的「已断开」分支触发 `ConnectedChanged(false)`，
  `HostController` 订阅它并立刻把光标收回本机。这条链路是「副机崩溃时主机不失控」的唯一保障。
- 所有 `Dispose()` 都是**幂等**的（`_disposed` 标志拦重复调用），
  避免 `App.OnExit` 与托盘「退出」两条路径重复释放。
- `SharingSession.Stop()` 先停控制器（补发抬起），再停发送泵，最后断连接——**顺序不能反**，
  反了就会出现「抬起事件还没发出去，连接已经没了」的粘键。

## 4. 资源与内存审查

### 4.1 委托保活（一个必踩的坑）

`SetWindowsHookEx` 传进去的委托**必须由托管代码持有强引用**。
若只写成 `SetWindowsHookEx(WH_MOUSE_LL, new LowLevelMouseProc(Callback), ...)` 而没存字段，
GC 一跑，系统回调的函数指针就变成野指针，进程直接崩（随机、难复现）。
`Core\Input\LowLevelHooks.cs` 用私有字段 `_mouseProc` / `_keyboardProc` 长期持有，**这是刻意的，不是冗余代码**。

### 4.2 事件订阅的对称性

每一处 `+=` 都有对应的 `-=`（或在 `Dispose` 里整体清空），
避免「窗口已关、会话还在往回推日志」这类难以察觉的泄漏。`Log` 是静态类、进程级生命周期，不涉及订阅泄漏。

### 4.3 Dispose 覆盖情况

8 个类实现了 `Dispose()`，全部通过 `using` 或 `App.OnExit` 的固定顺序调用：

| 类 | Dispose 做的事 |
| --- | --- |
| `LowLevelHooks` | `UnhookWindowsHookEx` 摘掉两个钩子 |
| `TcpTransport` | 关套接字，唤醒阻塞读线程 |
| `PeerConnection` | 停心跳定时器，断连接 |
| `FramePump` | 置停止标志，唤醒发送线程并 Join |
| `HostController` | 订阅解绑，释放按键 |
| `ClientController` | `ReleaseAll()` 补发所有抬起 |
| `SharingSession` | 按固定顺序停各部件 |
| `TrayIconService` | `NotifyIcon.Visible = false` 并释放图标（**不释放会在托盘留一个幽灵图标**） |

## 5. 性能审查

### 5.1 延迟预算

| 环节 | 实测/设计值 | 优化手段 |
| --- | --- | --- |
| 钩子回调 | 微秒级 | 只算坐标 + 入队 |
| 队列到发送 | 立即唤醒 | 发送线程优先级 `AboveNormal` |
| TCP 协议头 | **关掉 Nagle** | `Core\Net\TcpTransport.cs:118` `client.NoDelay = true` |
| 套接字缓冲 | 收发各 64 KB | `Core\Net\TcpTransport.cs:119-120` |
| 关闭 linger | `LingerState(false, 0)` | 断线立刻释放，不拖超时 |
| 坐标编码 | 整数运算，无浮点 | `(pixel * 65536L) / extent`，与系统 `(dx*cxScreen)>>16` 对齐 |

### 5.2 移动帧合并（带宽与延迟的取舍）

鼠标 1000 Hz 采样会淹没网络，所以 `FramePump` 做了**有选择的合并**：

- **只合并 `mouse_move`**，且只在「队尾也是 `mouse_move`」时就地覆盖，保留最新位置；
- **按键、滚轮、键盘绝不合并**——丢一个抬起事件就是粘键，丢一个滚轮就是一格没滚动；
- 合并可观测：`SentCount + CoalescedCount + DroppedCount + FailedCount == 提交数`，
  这条守恒律是自动化断言之一（实测提交 201、发出 1、合并 200、丢弃 0、失败 0）。

**关键不变量**：合并可以丢中间态，**绝不能丢最终位置**。否则表现为「鼠标停下时停在错误的地方」。

### 5.3 CPU 占用

- 心跳定时器 1 秒一次（`HeartbeatIntervalMs = 1000`），空闲时不发别的包；
- 无消息时接收线程阻塞在 `Socket.Receive`，不吃 CPU；
- UI 不做轮询刷新，只在事件到达时更新状态胶囊；
- 日志同步加锁写，但只有连接状态/切换/错误才写，**不进钩子回调热路径**。

### 5.4 日志体积控制

按天分文件，单文件超过 **2 MB**（`Core\Diagnostics\Log.cs:21`）自动滚动编号，
格式是「时间 + 级别 + 线程 + 消息」，不记录任何按键内容——既是隐私要求，也避免日志被高频输入事件撑爆。

## 6. 异常处理审查

- **启动期**：`App.OnStartup` 挂 `DispatcherUnhandledException`、`AppDomain.UnhandledException`、
  `TaskScheduler.UnobservedTaskException` 三个口子，漏网异常先写日志再弹中文提示，而不是白屏退出。
- **钩子回调**：`LowLevelHooks` 里每个回调整体包在 `try { } catch { }` 里。
  理由很硬：回调抛异常会沿系统栈传播，把宿主进程带走；宁可吞掉一次事件。
- **网络**：`UpdateChecker.Check()` 保证**不抛异常**，失败以 `UpdateInfo.Error` 返回，
  HTTP 404 提示「仓库还没有发布任何 Release」、403 提示「超出每小时 60 次匿名配额」。
- **配置**：`AppConfig.Load(out warning)` 逐字段容错，坏字段用默认值并累积到 warning，
  手工改坏的 config.json 不会让程序起不来。
- **日志**：`Log` 里所有写入失败都被吞掉——日志永远不能让主流程崩溃。

## 7. 已知不足（诚实清单）

| 项 | 现状 | 影响 | 后续方向 |
| --- | --- | --- | --- |
| 多显示器 | 有接口无实现 | 主显示器之外的区域不参与边缘判定 | 按显示器枚举建边缘表 |
| 剪贴板 / 文件拖拽 | 未实现 | 不能跨机复制粘贴 | 协议层已留位置 |
| UAC 安全桌面 | 无法控制 | 提权弹窗期间键鼠留在本机 | Windows 设计限制，用户态无解 |
| 拖拽时切换 | 不处理 | 按住左键拖到边缘不会完成跨屏拖拽 | 需要拦截鼠标捕获变化 |
| 单一客户端 | 主机一次只服务一个副机 | 三台以上不支持 | 需要连接管理表 |
| 传输加密 | 有握手 HMAC 校验，**后续帧是明文** | 同网段抓包可看到坐标与按键码 | 第一版目标是局域网可用 |

> 最后一条值得强调：`PairingKey` 的作用是**防止误连**（同网段别人的机器连上来），不是防窃听。
> 本程序假设局域网本身是可信网络。
