# LanMouseShare 技术架构

> 版本：1.0.0.0 · 语言：C# / WPF · 目标框架：.NET Framework 4.8（net48） · 平台目标：AnyCPU
> 仓库：<https://github.com/Zxin-Pro/LanMouseShare>

本文写给要看代码的人：讲清楚**数据怎么流**、**模块怎么分**、以及每个关键取舍**为什么这么做**。

## 1. 总览

一句话：**主机装全局钩子把真实输入截下来，算好坐标后走 TCP 发给副机，副机用 `SendInput` 把动作放出来。**

- 主机 = 接了鼠标键盘的那台，装钩子、做判定、发帧。它是**监听方**（TCP 服务端）。
- 副机 = 没接的那台，收帧、执行。它是**连接方**（TCP 客户端），**不装任何钩子**。

## 3. 协议

### 3.1 帧格式

- **一行一条消息**：UTF-8 JSON，以 `\n` 结尾。
- 单帧上限 `ProtocolCodec.MaxFrameBytes = 64 * 1024`。
- 协议版本 `PeerConnection.ProtocolVersion = "LMS/1"`，握手时校验，不匹配直接拒绝。
- 帧的公开字段名就是 JSON 键名：`type / version / nonce / mac / accepted / note / screenWidth / screenHeight / nx / ny / button / down / wheel / horizontal / vk / scan / extended / stamp`。
- 鼠标坐标 `nx / ny` 一律是 **0..65535 归一化值**（与 `MOUSEEVENTF_ABSOLUTE` 的空间完全一致）。

### 3.2 消息类型（`Core\Net\Frame.cs` 的 `Msg` 类）

| 类型 | 方向 | 说明 |
| --- | --- | --- |
| `hello` | 主机 → 副机 | 携带协议版本与 16 字节随机 nonce |
| `auth` | 副机 → 主机 | 携带 `PairingKey.ComputeMac()` 的结果：对「协议版本 + 竖线 + nonce」做 HMAC-SHA256 |
| `auth_result` | 主机 → 副机 | 认证结果（`accepted`），不通过就不给转发 |
| `screen_info` | 双向 | 上报本机主显示器分辨率。副机认证通过后先发，主机收到后回发自己的 |
| `mouse_move` | 主机 → 副机 | 归一化坐标移动（可被合并） |
| `mouse_button` | 主机 → 副机 | `button` = `left` / `right` / `middle` / `x1` / `x2`，`down` 表示按下或抬起 |
| `mouse_wheel` | 主机 → 副机 | `wheel` 为 ±120 的整数倍，`horizontal` 区分水平滚轮 |
| `key` | 主机 → 副机 | `vk` + `scan`（扫描码）+ `extended` + `down` |
| `ping` / `pong` | 双向 | 心跳，每 1000 ms 一次 |
| `bye` | 双向 | 主动断开 |
| `notice` | 主机 → 副机 | 提示信息，副机显示到日志 |

### 3.3 握手时序

```
副机                                                       主机
  │                                                          │
  │  ── TCP 连接 24800 ─────────────────────────────────────► │   （主机在监听）
  │                                                          │
  │  ◄──────── hello { version:"LMS/1", nonce:<16B 随机> } ── │
  │                                                          │
  │  ── auth { mac: HMAC-SHA256(key, version+"|"+nonce) } ─► │   主机用同一密钥验签
  │                                                          │
  │  ◄──────── auth_result { accepted:true } ─────────────── │
  │                                                          │
  │  ── screen_info { screenWidth, screenHeight } ─────────► │   副机上报分辨率
  │  ◄──────── screen_info { ... } ───────────────────────── │   主机回发自己的
  │                                                          │
  │  ◄══════════ mouse_move / mouse_button / key ════════════ │   只有认证通过才发业务帧
```

`auth` 摘要在代码里的确切表达式（`Core\Net\PairingKey.cs`）：

```
HMAC-SHA256(key, protocolVersion + "|" + nonce)
```

认证通过前 `PeerConnection.SendAuthenticated` 会直接拒绝发送业务帧。

**密钥本身永远不上网**，网络上只出现它的 HMAC 摘要；nonce 每次连接随机，因此重放攻击无效。

> ⚠️ **注意：协议内容是明文 JSON，传输层没有加密。** 全仓库没有任何 TLS/加密实现，HMAC 只用于握手认证，不用于业务帧的保密。设计前提是「**只在可信局域网内使用**」（与项目定位一致）。若要在不可信网络使用，需要自行加一层隧道（VPN / SSH 端口转发）。

## 4. 关键设计决策

### 4.1 钩子回调里绝不做重活

**做法**：`LowLevelHooks` 的回调里**只做内存判断**（看签名、看坐标、判断要不要吞），需要发给副机的动作只是往 `FramePump` 的队列里 `Post` 一下（微秒级），真正的网络发送交给发送泵线程。

**为什么**：`WH_*_LL` 钩子的回调是有**超时预算**的，系统给的是 **300 毫秒**。一旦回调超时，系统会**静默地把你的钩子摘掉** —— 不报错、不抛异常、日志里什么都不会有，表现就是「**共享莫名其妙就停了**」。这类问题极难排查，所以宁可多一层队列，也绝不在回调里发网络包或碰磁盘。

配套的两条纪律：

- 委托实例必须用字段保存住，否则会被 GC 回收，留下**野指针**，直接崩掉钩子链；
- 回调整体包在 `try / catch` 里，异常一旦逃出回调会破坏钩子链，严重时**卡死整个鼠标**。

### 4.2 防自激死循环：靠 `dwExtraInfo` 签名，不靠时间窗

**做法**：`InputInjector.InjectionSignature = 0x4C4D5348`（ASCII 就是 `'LMSH'`）。每一次 `SendInput` 都把签名写进 `dwExtraInfo`。回调里用 `IsInjected` 判断：

```csharp
// 伪码：三级判定，命中任意一条即视为「非真人操作」
extraInfo == new IntPtr(InputInjector.InjectionSignature)   // 自己注入的
  || (flags & LLMHF_INJECTED) != 0                         // 任何程序注入的
  || (flags & LLMHF_LOWER_IL_INJECTED) != 0                // 低完整性级别进程注入的
```

**为什么不用时间窗**（「刚注入完 100 ms 内的事件一律忽略」）：时间窗在用户**高速移动鼠标或快速连按**时会**误杀真人操作** —— 用户手速比窗口还快，动作就被丢了。而 `dwExtraInfo` 签名是**精确的、零误判的**：只认自己盖的章。

另外，**别的程序注入的事件同样放行**（远程桌面、自动化脚本、宏工具）—— 程序不去拦截别人，避免多个工具互相打架。

> 这条规则还解决一个隐藏的坑：副机收到帧后调 `SendInput`，如果**副机自己也装了钩子**就会被自己的注入事件再次触发，形成无限回环。签名判定天然挡掉了它（而且副机本来就不装钩子，见 4.5）。

### 4.3 坐标用 0–65535 归一化传输

**做法**：`CoordinateMapper.NormalizedMax = 65535`。

- 正向：`normalized = pixel * 65536 / width`
- 反向：`pixel = normalized * width / 65536`

**为什么**：两台机器的分辨率可以完全不同（1920×1080 对 2560×1440）。归一化之后，主机**只需要知道「鼠标在屏幕宽度的百分之几」**，副机按自己的分辨率还原即可 —— 换显示器、改分辨率、两台机器不一样，**都不用改代码也不用改配置**。

顺带一个细节：这里故意用 `* 65536 / width` 而不是 `* 65535 / (width-1)`，是为了**和 Windows 自己的坐标换算对齐**（系统内部就是 `(dx * cxScreen) >> 16`），这样往返换算**边缘不差 1 像素**。

### 4.4 移动帧可以合并，按键和滚轮绝不合并

**做法**：`FramePump` 里维护一个上限 512 帧的队列。`Post` 进队时，**只有队尾也是 `mouse_move`** 才就地覆盖（`tail.Value = frame`，计数 `Coalesced`），否则追加。队列超限时只丢**最老的 `mouse_move`**（计数 `Dropped`），**按键事件一条都不丢**。

**为什么**：

- 游戏鼠标 1000 Hz 上报，一秒就是 1000 帧。原样转发足以喂满 100 Mbps 局域网，副机指针会**明显滞后**。
- 移动是**状态**，不是事件：丢了中间位置不影响最终结果，只保留最新位置就够了。
- **按键和滚轮是事件**：漏掉一个「按下」或「抬起」，副机上就会出现粘键或者点击丢失，这是不可接受的。
- 合并**只发生在队尾也是移动帧时**，所以 `move, click, move` 这样的先后顺序不会乱 —— **拖拽不会被玩坏**。

### 4.5 副机不装任何钩子

**做法**：`ClientController` 只做三件事：收帧 → 用 `SendInput` 还原；跟踪「当前按下了哪些鼠标键和按键」；链路断掉时把残留的全部补发抬起。

**为什么**：

- **光标该去哪、什么时候该划回主机，全部由主机算好。** 副机完全不需要知道主机长什么样、屏幕几块、分辨率多少 —— 不同分辨率、将来上多显示器，副机侧一行都不用改。
- 钩子是**资源**，也是**风险**（安全和稳定性）。能在副机省掉一整套全局钩子，就少一半的故障面。
- 副机侧逻辑越薄，越不容易出「两台机器互相打架」的问题。

### 4.6 DPI 感知必须在 `app.manifest` 里声明

**做法**：`app.manifest` 同时写：

```xml
<dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
<dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">permonitorv2,permonitor</dpiAwareness>
```

运行时 `DpiAwareness.TryEnableBestAvailable()` 仍会按三级回退尝试（`SetProcessDpiAwarenessContext` → `SetProcessDpiAwareness` → `SetProcessDPIAware`），但**清单声明才是主力**。

**为什么**：**进程一旦启动，DPI 感知级别就锁死了。** 实测结论：

- 一个 WPF 进程即使完全不声明 DPI，启动时进程的感知级别**已经是 1（系统级）**；
- 此时再去调两个更高级别的 API，**全部返回 `E_ACCESSDENIED`（`0x80070005`，Win32 错误码 5）**；
- 更阴的是 `SetProcessDPIAware()` 在这种「已锁死」的情况下**依然返回 `true`** —— 只看返回值会把「实际是每显示器 V2」误报成「系统级」。

所以 `DpiAwareness` 的实现里有两条反直觉但必要的规则：

1. **每次 API 声称成功后都回读真实级别**（`GetThreadDpiAwarenessContext` → `GetProcessDpiAwareness` → `IsProcessDPIAware` 三级），**回读结果优先于返回值**；
2. 回读比较必须用 `AreDpiAwarenessContextsEqual`，**不能直接比数值**：`GetThreadDpiAwarenessContext` 返回的是真正的句柄，在 Win11 26200 上实测是 `34` / `24592` 这种值，**不是** `-1 / -2 / -3 / -4` 那几个伪值，直接比数值**永远错**。

清单里另外两处也是**必须**的：

- `<requestedExecutionLevel level="requireAdministrator">`：不提权时低级钩子**静默失效**。
- `supportedOS` **必须包含 Win10 的 GUID**（`{8e0f7a12-bfb3-4fe8-b9a5-48fd50a15a9a}`）。缺了它，**Win10 / Win11 会把自己谎报成 Win8**，后续行为会按 Win8 走。

> Win7 上 `permonitorv2` 不可用，只能回退到**系统级** `SetProcessDPIAware()`，这是已知限制。另外 `VirtualScreen` 用 `GetSystemMetrics` 取到的尺寸因为进程声明了 PerMonitorV2 而天然是**物理像素** —— 如果去掉清单里的 DPI 声明，这里就会拿到缩放过（假）的尺寸，坐标换算全线出错。

### 4.7 AnyCPU 下 `INPUT` 结构体大小不同，`cbSize` 必须现算

**做法**：`InputInjector` 里

```csharp
private static readonly int InputSize = Marshal.SizeOf(typeof(NativeMethods.INPUT));
```

每次填 `cbSize` 都用这个值，**绝不写死常量**。

**为什么**：项目编译为 **AnyCPU**，同一个 EXE 在 64 位系统上跑成 64 位进程、在 32 位系统（或做了 32 位限制的场景）上跑成 32 位进程。而 `INPUT` 结构体里含有指针宽度的成员，**32 位下是 28 字节，64 位下是 40 字节**。写死任何一个值，在另一种进程里 `SendInput` 就会直接失败（返回 0，什么都不动）—— 而且失败是**静默的**。

> 项目公开了 `InputInjector.InputStructSize` 便于诊断时确认当前进程用的是哪个尺寸。

### 4.8 退出和断线都要补发「抬起」，否则副机会粘键

**做法**：两处都做收尾：

- **主机侧**：`HostController.Stop()` 里**先 `ReleaseRemoteHold()` 再摘钩子**；`PeerConnection.ConnectedChanged(false)` 订阅里立刻 `ForceReturnLocal()` 把光标收回本机。
- **副机侧**：`ClientController` 用 `HashSet<MouseButtonKind>` 和 `HashSet<int>` 记住当前按下的鼠标键与按键，`ReleaseAll()` 对每一个残留项补发一次「抬起」，并记录日志「已补发抬起事件：N 个鼠标键、M 个按键」。

**为什么**：假设用户正按着 Ctrl 或拖着鼠标左键时断线了。如果不补发抬起：副机永远认为那个键还按着 —— 表现是「**一直按住 Ctrl**」，用户只能重启副机上的程序才能恢复；鼠标左键则会变成**一直在拖拽**。这类状态残留在两端都存在，所以两端都要兜底。

> 主机端 `ConnectedChanged` 的订阅是**强制**的：掉线时如果不立刻把光标收回本机，光标会**留在副机上**，而本机再也收不到任何输入事件 —— 这台机器等于**整台失控**。

## 5. 线程模型

| 线程 | 创建者 | 职责 | 关键约束 |
| --- | --- | --- | --- |
| **WPF UI 线程**（STA，带消息泵） | WPF / `App.OnStartup` | 设置 DPI 感知、装配所有对象、创建窗口与托盘、**安装/卸载钩子**、**执行钩子回调**、刷新界面 | 低级钩子**必须**在有消息泵的线程上安装（就是这里）。因此**钩子回调跑在 UI 线程上** —— 回调里做重活会同时**卡住界面**和**触发 300 ms 摘钩** |
| **心跳 Timer 线程**（ThreadPool） | `PeerConnection`，`new Timer(OnHeartbeat, null, 1000, 1000)` | 每 1000 ms 发 `ping`；判定 5 秒无帧则断线 | 回调里会加锁并写 socket，所以只做收发与状态判定 |
| **网络接受线程** `lms-accept` | `TcpTransport.StartListen`（`IsBackground = true`） | 主机侧 `Accept` 循环 | 接受成功后为该连接启动 `lms-read` |
| **网络读线程** `lms-read` | `TcpTransport`（`StartListen` / `Connect` 成功后，`IsBackground = true`） | 收字节 → `ProtocolCodec.Append` 拆粘包 → 触发 `FrameReceived` | **副机的 `SendInput` 就是在这个线程上执行的**；主机侧的 `screen_info` 处理也在它上面 |
| **发送泵线程** `lms-frame-pump` | `FramePump.Start`（`IsBackground = true`，`Priority = AboveNormal`） | `AutoResetEvent` 唤醒 → 从队列取帧 → `SendAuthenticated` | 队列上限 512；只丢最老的 `mouse_move`，按键帧一律保留 |

### 5.1 跨线程同步方式

| 场景 | 机制 |
| --- | --- |
| 钩子回调 → 发送队列 | `FramePump` 内 `LinkedList<Frame> _queue` + `object _sync` 锁 + `AutoResetEvent _signal`（经典生产者/消费者）。`Post` 只锁极短的一段，保证回调内是微秒级 |
| 队列空时发送泵 | `_signal.WaitOne(2)` 带 2 ms 超时等待，既能被立刻唤醒，也不会永久阻塞导致 `Dispose` 卡住 |
| 副机按下状态 | `ClientController` 内 `lock (_sync)` 保护两个 `HashSet` |
| 连接状态与发送 | `PeerConnection` 内部锁；`SendAuthenticated` 在未认证时直接拒绝 |
| 日志写入 | `Log` 在锁内写入，**任何写入失败都被吞掉**（日志永远不能让主流程崩溃） |
| 钩子委托生命周期 | 委托实例保存在**字段**里，防止 GC 回收导致野指针 |
| **Core → UI 的更新** | Core 层**完全不碰 `Dispatcher`**（全仓库 `Core\` 下零处 `Dispatcher` 引用）。所有跨线程回界面的动作都由 `MainWindow` 自己用 `Dispatcher.BeginInvoke` 派发（MainWindow.xaml.cs:648、682、691、699、881） |

设计取向很明确：**Core 层是纯同步的、线程安全的、不知道 UI 存在的组件**；界面通过 `SharingSession` 这一层订阅事件（`Log` / `LocationChanged` / `ConnectedChanged` / `RemoteScreenKnown`）拿到通知，再决定怎么派发回 UI 线程。

## 6. 坐标与布局几何

`ScreenLayout` 把两台电脑拼成一张**合成桌面**。主机永远占据 `[0,0,HostWidth,HostHeight]`，副机按方向和偏移贴在旁边：

| 方向 | 副机原点 | 偏移的方向 |
| --- | --- | --- |
| `Right` | `(HostWidth, OffsetPixels)` | 沿贴合边**上下**挪 |
| `Left` | `(-RemoteWidth, OffsetPixels)` | 沿贴合边**上下**挪 |
| `Above` | `(OffsetPixels, -RemoteHeight)` | 沿贴合边**左右**挪 |
| `Below` | `(OffsetPixels, HostHeight)` | 沿贴合边**左右**挪 |

关键常量与判定：

- `ScreenLayout.DefaultReturnGuard = 4`：**回程守卫**，从副机划回主机时必须真正越过边缘 4 像素才生效。
- `ScreenLayout.RecenterMargin = 8`：光标进入距边缘 8 像素内就把主机光标 `SetCursorPos` 搬回屏幕中心。
- `TryExitHost`：要求光标**顶在贴合边上**（例如 Right 要求 `hostX >= HostWidth - 1`）**并且位移方向朝外**（`dx > 0`）才穿越。副机分辨率未知（`RemoteKnown == false`）时**一律不穿越** —— 否则光标会落到不存在的位置。
- `TryExitRemote`：用**未夹紧的虚拟坐标**判断回程，必须真正越过 `ReturnGuard`。
- `ScaleDelta`：两屏尺寸不同的等比缩放。**缩放结果为 0 而原始位移不为 0 时保底返回 ±1**，防止慢速移动被整除抹成 0 造成「粘住」。
- `NeedsRecenter`：见下面的取舍说明。

### 6.1 两个「不用时间窗」的防抖

程序里所有防抖都用**物理量**而不是时间，这是刻意的：

1. **穿越必须伴随朝向边缘的真实位移。** 光标停在边缘、或者被别的程序人为停在边缘时，**绝不误触发**。相比之下「N 毫秒内不重复切换」的时间窗在用户**快速来回划**时会**漏掉合法切换**（用户手速比窗口快）。
2. **回程必须多走 `ReturnGuard` 像素。** 简单、可预测，不会因为系统卡顿误判。

### 6.2 为什么 Remote 模式下不吞鼠标移动

这是整个项目最反直觉的一个取舍，代码注释里写得很明白：

> 低级钩子**只能拿到光标坐标**，位移是靠**前后两次坐标相减**算出来的。

如果 Remote 模式下把鼠标移动也吞掉（`Handled = true`），系统会把光标**钉在屏幕边缘**，于是后续两次回调拿到的坐标**完全一样，位移永远是 0** —— 表现就是「**鼠标划到副机边缘就卡住不动**」。

所以 `HostController` 在 Remote 模式下**只吞按键和滚轮，移动一律放行**，同时用 `SetCursorPos` 在光标接近边缘（`RecenterMargin = 8` 像素内）时把它**搬回屏幕中心**，保证位移永远有得读。

> 因为此时用户正看着另一块屏幕，主机光标被搬回中心**在视觉上是不可见的**。这是一个用「看不见的副作用」换「可靠读取位移」的典型工程折中。

## 7. 已知限制

| 限制 | 原因 |
| --- | --- |
| **只支持单显示器** | 第一版 MVP 范围。`VirtualScreen` 已经能识别多显示器（`IsMultiMonitor`），但布局模型只覆盖一个矩形 |
| **剪贴板共享 / 文件拖拽未实现** | 接口预留，第一版未实现 |
| **UAC 安全桌面 / `Ctrl+Alt+Delete` 期间失效** | Windows 安全桌面会屏蔽钩子与 `SendInput`。**用户态程序无法绕过**，键鼠会留在原机器上 |
| **传输层无加密** | 业务帧是明文 JSON，只有握手阶段有 HMAC 认证。前提是「可信局域网」 |
| **需要管理员权限** | 全局低级钩子 + `SendInput` 向其他进程注入的硬性要求；`app.manifest` 声明 `requireAdministrator`，**每次启动弹 UAC** |
| **Win7 只能到系统级 DPI** | `permonitorv2` / `SetProcessDpiAwareness` 在 Win7 上不存在，只能回退到 `SetProcessDPIAware()` |
| **一个主机同时只服务一个副机** | `PeerConnection` 是单连接的 |
| **主机光标会被 `SetCursorPos` 搬动** | 见 6.2，这是「能读到位移」的代价；副作用对用户不可见 |
| **归一化坐标空间是主显示器** | `MoveAbsolute` 不带 `MOUSEEVENTF_VIRTUALDESK`，与单显示器 MVP 一致 |
| **`SendInput` 可能被 UIPI 拦** | 向更高完整性级别进程注入时失败，且返回的是「成功注入的事件数」而不是布尔值，程序按数量判定 |

## 8. 后续可扩展点

代码里已经埋好的接口：

| 方向 | 已有的基础 | 还需要做什么 |
| --- | --- | --- |
| **多显示器** | `VirtualScreen` 已提供 `VirtualLeft/Top/Width/Height` 与 `IsMultiMonitor` | 把 `ScreenLayout` 的单矩形模型扩展成区域列表；`MoveAbsolute` 加上 `MOUSEEVENTF_VIRTUALDESK` |
| **剪贴板共享 / 文件拖拽** | 帧协议是「一行一条类型化消息」，加类型成本很低；`notice` 已示范了非输入类消息的通道 | 新增消息类型 + 主机侧剪贴板监听（这本就是钩子/消息循环的既有能力） |
| **锁定指针模式（指针不越屏）** | `InputInjector.MoveRelative` 已经实现（当前主要给调试用） | 接上配置开关与状态机分支 |
| **传输加密** | 编解码集中在 `ProtocolCodec` / `TcpTransport` 两个入口 | 在这两处之间插入一层对称加密，业务层无感 |
| **多副机** | `FramePump` / `HostController` 的职责边界清楚 | `PeerConnection` 从单连接改成连接集合，`ScreenLayout` 支持多个副机矩形 |
| **服务化 / 无界面运行** | 命令行已经有 `--host` / `--client` / `--selftest` / `--nettest` 这一整套无界面路径 | 把 `App` 的装配顺序搬到服务宿主里 |
| **自动发现主机** | `NetworkInfo` 已能探测本机局域网地址 | 加一层 UDP 广播/组播握手，省掉手填 IP |
