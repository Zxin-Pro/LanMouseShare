# LanMouseShare 部署与安装

> 适用版本：1.0.4.0 · 平台：Windows 7 SP1 / Windows 10 / Windows 11（32 位与 64 位进程均可运行）
> 仓库：<https://github.com/Zxin-Pro/LanMouseShare>

本文写给**负责装机的人**。整套部署在两台电脑上各做一遍，区别只有一处：**只有主机需要放行防火墙端口。**

**主机** = 接了鼠标键盘的那台；**副机** = 没接的那台，由主机把输入转发过来。

## 1. 系统要求

| 项目 | Windows 7 SP1 | Windows 10 | Windows 11 |
| --- | --- | --- | --- |
| 系统版本 | 必须已安装 **Service Pack 1**（未装 SP1 的 Win7 不支持） | 任意版本 | 任意版本 |
| .NET Framework 4.8 | **需要手动安装**（见第 2 节，含两个前置补丁） | **通常已内置**，不用装 | **已内置**，不用装 |
| 位数 / 架构 | 32 位、64 位均可 | 32 位、64 位均可 | 64 位 |
| 内存 | ≥ 2 GB | ≥ 4 GB | ≥ 4 GB |
| 网络 | 与另一台在同一局域网，能互相 ping 通 | 同左 | 同左 |
| 权限 | 需要管理员权限（每次启动会弹 UAC，见第 3 节） | 同左 | 同左 |
| DPI 感知 | **只能到系统级**，不做每显示器 DPI | 每显示器 DPI（V2） | 每显示器 DPI（V2） |
| 显示器 | **第一版只支持单显示器** | 同左 | 同左 |

两点补充说明：

- **为什么不用 .NET 8 / .NET Core**：Win7 SP1 装不了现代 .NET 运行时。为了守住「Win7 SP1 也要能跑」这条硬需求，项目目标框架锁定 .NET Framework 4.8，编译为 AnyCPU。
- **更早的 Windows 10（1903 之前）可能没有内置 4.8**，那就按第 2.3 节的方法自己装一次，补丁不用装（那是 Win7 才需要的）。

## 2. 安装 .NET Framework 4.8

### 2.1 Windows 10 / 11：通常什么都不用做

Windows 10（1903 及以后）与 Windows 11 已内置 .NET Framework 4.8 或更高版本，直接跳到第 3 节。

想确认一下是否已装，打开命令行执行：

```
reg query "HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full" /v Release
```

看返回的 `Release` 值：**≥ 528040** 就说明已经是 4.8 或更高，可以直接用。若提示找不到项或值偏小，就按 2.3 节装一次。

### 2.2 Windows 7 SP1：三步，顺序不能反

> ⚠️ **Windows 7 已于 2020 年 1 月停止支持，微软官方可能已下线部分下载链接。** 请优先从微软官方渠道获取；若官方链接失效，请在公司/组织内部的软件仓库中确认合法来源后再安装。本站文档只说明步骤，不提供安装包。

Win7 SP1 装 .NET Framework 4.8 必须**先装两个前置补丁**，因为 4.8 的安装包是 SHA-2 签名的，而没打过补丁的 Win7 只认 SHA-1 签名 —— 这正是「证书链被吊销 / 安装程序报签名无效」这类错误的根因。

**第 1 步：装 KB4490628（SHA-2 代码签名支持）**

- 文件名形如 `windows6.1-kb4490628-x64.msu`（32 位系统是 x86）。
- 这个补丁给 Win7 加入 SHA-2 代码签名验证能力。

**第 2 步：装 KB4474419（SHA-2 签名补丁）**

- 文件名形如 `windows6.1-kb4474419-v3-x64.msu`。
- 注意：**必须放在 KB4490628 之后**。顺序装反会导致后续 .NET 安装失败。

**第 3 步：装 .NET Framework 4.8 运行时**

- 安装包：`ndp48-x86-x64-allos-enu.exe`（同时覆盖 32 位与 64 位）。
- 双击运行，按向导完成。

**第 4 步：重启电脑**

- 装完**必须重启**，否则新运行时的注册表和程序集缓存没有生效，LanMouseShare 启动时会报「需要 .NET Framework 4.8」。

**装完验证一下**（在 Win7 上也用同一条命令）：

```
reg query "HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full" /v Release
```

`Release` ≥ 528040 即安装成功。

### 2.3 备用方案

如果 4.8 在你的环境里确实装不上（老镜像、精简系统、组策略限制），可选的办法只有两条：

1. 先打满 Windows Update（Win7 需要先装 SHA-2 支持才能收到后续更新），再重试 4.8。
2. 找一台已经装好 .NET Framework 4.8 的同版本机器做系统镜像。

不建议去第三方站点下「离线整合包」，来源不明的 .NET 安装包是重灾区。

## 3. 安装 LanMouseShare

两种装法，挑一个。

### 3.1 安装版（推荐）：一个 exe 装好

1. 双击 `LanMouseShare-<版本>-setup.exe`。
2. Windows 会弹 **UAC 提权提示**，点 **「是」**（安装程序自己也要管理员权限）。
3. 它会先检查 .NET Framework 4.8。**没装就直接告诉你**并给出微软官方下载页；装了就直接点「安装」。
4. 装完：程序在 `%LOCALAPPDATA%\Programs\LanMouseShare\`，桌面和开始菜单各有一个快捷方式，在「控制面板 → 程序和功能」里能看到 **LanMouseShare · 局域网键鼠共享**。

想装到别处就加 `--dir=<路径>`；无人值守装机用 `--silent`（配 `--nolaunch` 装完不启动）：

```
LanMouseShare-1.0.4.0-setup.exe --silent --nolaunch --dir=D:\LanMouseShare --log=D:\setup.log
```

日志默认写在 `%TEMP%\LanMouseShareSetup.log`，也可以用 `--log=<路径>` 指定。

> 安装程序是**图形子系统程序**，cmd 启动它之后不会等它跑完，所以 `setup.exe --silent > out.txt` 里的 `out.txt` 永远是空的。要看输出就读 `--log` 指定的那个文件。

### 3.2 免安装版：解压就能用

1. 把 `LanMouseShare-<版本>-win.zip` 解压到一个**位置简单、路径短**的目录，例如 `C:\Tools\LanMouseShare` 或 `D:\LanMouseShare`。
   - 建议避开中文深层路径（某些老系统上的解压/杀软组合会在这里出问题）。
   - 也避开 `C:\Program Files` 下的多层中文目录；程序本身不往安装目录写任何东西（配置和日志都在用户目录，见第 7 节），所以放哪都能跑。
2. 确认目录里有 `LanMouseShare.exe`、README、docs 目录。

### 3.3 两种装法都要做的：首次启动

1. **双击 `LanMouseShare.exe`。**
2. Windows 会弹出 **UAC 提权提示（用户账户控制）**，点 **「是」**。

> **每次启动都会弹 UAC，这是设计如此，不是装错了。**
> 程序清单里声明了 `requireAdministrator`。原因有三条：
> 1. 不提升权限时，全局低级键鼠钩子（`WH_MOUSE_LL` / `WH_KEYBOARD_LL`）**无法向高完整性级别的进程注入**（例如任务管理器、以及任何在 UAC 之后启动的程序），而且它是**静默失效**的 —— 表现是「共享莫名其妙对某些窗口不起作用」，极难排查；
> 2. `SendInput` 向其他进程发送输入，同样需要足够的完整性级别；
> 3. 注册全局热键、读写本机配置也需要相应权限。
>
> 如果不想每次手点 UAC，见第 5.2 节的任务计划程序做法。

## 4. Windows 防火墙放行 24800 端口

**只有在【主机】上需要放行。** 副机是主动连接的一方，它发起的是出站连接，Windows 防火墙默认就允许出站，不用加规则。

> **主机点「开始共享」时，程序自己会把这个规则建好**：它用 `netsh advfirewall` 建一条入站放行规则（域 / 专用 / 公用三档全放行），日志里会写「防火墙放行：已自动添加规则」。
>
> 所以正常情况下**你什么都不用做**。Win10 / Win11 对已经带管理员清单、又主动监听的进程，经常一声不吭就把入站包丢掉，两边日志都看不出问题——这正是程序自己动手建规则的原因，不再依赖 Windows 那个时有时无的弹窗。
>
> 如果仍然弹了「是否允许 LanMouseShare 访问网络」，选「允许」并勾上专用网络。规则没建成功时（比如程序不是以管理员身份跑的），就按下面两种办法之一手动加。

### 4.1 图形界面做法（高级安全 Windows Defender 防火墙）

1. 按 `Win + R`，输入 `wf.msc`，回车（或者在「控制面板 → 系统和安全 → Windows Defender 防火墙 → 高级设置」打开）。
2. 左侧选中 **「入站规则」**。
3. 右侧点 **「新建规则…」**。
4. 规则类型选 **「端口」**，下一步。
5. 选 **「TCP」**，在「特定本地端口」里填 **`24800`**，下一步。
6. 选 **「允许连接」**，下一步。
7. 配置文件三个都勾上（域 / 专用 / 公用；至少勾「专用」），下一步。
8. 名称填 **`LanMouseShare`**，完成。

> 如果你在程序里把端口改成了别的值，防火墙规则里也要跟着改成同一个端口。

### 4.2 命令行做法（管理员命令行，一条搞定）

以管理员身份打开命令提示符或 PowerShell，执行：

```
netsh advfirewall firewall add rule name="LanMouseShare" dir=in action=allow protocol=TCP localport=24800
```

验证规则是否建好：

```
netsh advfirewall firewall show rule name="LanMouseShare"
```

卸载时删除这条规则：

```
netsh advfirewall firewall delete rule name="LanMouseShare"
```

> **只需要在主机上做这件事。** 如果两台都放行了也不会有副作用，只是没必要。

### 4.3 换端口

默认 TCP 端口是 **24800**。如果被占用（或公司策略不允许），可以在两台电脑的「共享」页里各自把「TCP 端口」改成同一个新值（例如 24801），然后：

- 主机：改完防火墙规则里的端口；
- 副机：**两边端口必须一致**，否则连不上。

## 5. 开机自动启动

这里有两件事，别混淆：

| 你想要的 | 设置位置 | 说明 |
| --- | --- | --- |
| 程序启动后**自动开始共享**，不用每次手点「开始共享」 | 主界面「共享」页勾选 **「程序启动时自动开始共享」** | 这是程序内置的选项（配置键 `autoStart`，默认关闭）。它**只管共享，不管开机启动** |
| 程序**随 Windows 一起启动** | 见下面 5.1 / 5.2 | 项目第一版未提供内置开关，用系统方式实现 |

### 5.1 简单做法：启动文件夹快捷方式

1. 按 `Win + R`，输入 `shell:startup`，回车，会打开当前用户的「启动」文件夹。
2. 在 `LanMouseShare.exe` 上右键 →「发送到」→「桌面快捷方式」，再把这个快捷方式**剪切到刚打开的启动文件夹**里。
3. 下次登录 Windows 时程序会自动启动。

**注意**：程序需要管理员权限，通过启动文件夹启动时**仍会弹一次 UAC**，需要点「是」。

### 5.2 免 UAC 的做法：任务计划程序（推荐给无人值守的机器）

1. `Win + R` 输入 `taskschd.msc`，打开任务计划程序。
2. 右侧 **「创建任务…」**（不要用「创建基本任务」）。
3. **「常规」**页：
   - 名称：`LanMouseShare`；
   - 勾选 **「使用最高权限运行」**；
   - 「配置」按系统选（Win7 选 Windows 7，Win10/11 选对应版本）。
4. **「触发器」**页 → 新建 → 开始任务选 **「登录时」** → 确定。
5. **「操作」**页 → 新建 → 操作「启动程序」→ 程序或脚本填 `LanMouseShare.exe` 的**绝对路径**。
6. **「条件」**页：把「只有在计算机使用交流电源时才启动此任务」取消（笔记本上很有用）。
7. **「设置」**页：可勾选「如果任务失败，按以下频率重新启动」。
8. 确定保存。

这样程序会在登录时以最高权限静默启动，**不弹 UAC**。

### 5.3 别忘了副机

副机不需要开机自启也能用（主机连过来时，副机上的程序必须在运行）。如果副机也是常年开着的机器，建议同样配上自启。

## 6. 杀毒软件 / 安全软件的注意事项

LanMouseShare 会做两件让安全软件敏感的事：

1. **安装全局低级键鼠钩子**（`WH_MOUSE_LL` / `WH_KEYBOARD_LL`）—— 这是键盘记录类软件常用的技术；
2. **模拟输入**（`SendInput`）—— 这是自动化/宏类软件常用的技术。

正规杀毒软件通常只是提示或放行，但**如果被拦，症状会非常隐蔽**：程序能启动、能连上，就是副机没反应，或者键盘不生效。请提前做好白名单：

1. 把 LanMouseShare 的整个安装目录加入**信任区 / 排除列表**（文件与目录都要）。
2. 如果有 HIPS / 主动防御 / 行为拦截，放行它的「键盘记录」「模拟输入 / 模拟点击」「全局钩子」行为。
3. 关掉针对本程序的**网络防护 / 端口扫描拦截**，或者把 24800 端口的入站流量排除。
4. 冲突源还包括：游戏加速器、输入法增强工具、鼠标驱动宏工具、远程桌面软件 —— 它们也会抢钩子，排查时可以临时退出它们。
5. **公司电脑的 EDR / 终端管控软件**可能直接禁止安装全局钩子。这种情况程序侧绕不过去，需要找 IT 加白名单。

## 7. 配置文件与日志在哪

程序**不往安装目录写任何东西**，全部数据在用户的本地应用数据目录：

| 内容 | 路径 |
| --- | --- |
| 配置文件（JSON，UTF-8） | `%LOCALAPPDATA%\LanMouseShare\config.json` |
| 日志文件（UTF-8，按天分割） | `%LOCALAPPDATA%\LanMouseShare\logs\LanMouseShare-yyyymmdd.log` |

- 在程序里点「诊断与更新」页的 **「打开配置目录」**，或托盘菜单的 **「打开配置目录(&F)」**，可以直接打开这个文件夹。
- 单份日志超过 2 MB 会自动滚动编号，不会无限增大。
- **日志只记录连接状态、屏幕切换、DPI、权限和错误**，绝不记录具体按键内容。

> 为什么放这里而不是程序目录：程序如果装在 `C:\Program Files`，普通用户对程序目录没有写权限，配置文件会写不进去。

**多用户注意**：`%LOCALAPPDATA%` 是**每个用户各自一份**的。同一台机器换个 Windows 账户登录，配置和日志都是新的，需要重新填连接密钥。

## 8. 验证装好了没有

### 8.1 快速验证：自检

在安装目录打开管理员命令行，执行：

```
LanMouseShare.exe --selftest=5
```

- `=5` 是自检秒数，程序跑 5 秒自检后**自动退出**。
- **退出码 `0` = 通过，`2` = 失败。** 在命令行里可以用 `echo %ERRORLEVEL%` 查看。
- 运行完打开日志文件：

  ```
  %LOCALAPPDATA%\LanMouseShare\logs\LanMouseShare-yyyymmdd.log
  ```

  日志末尾出现这一行就是通过：

  ```
  SELFTEST RESULT: PASS
  ```

  上面还会有若干行逐项结果，形如 `[PASS] 项目名 —— 说明`。出现 `SELFTEST RESULT: FAIL` 就按失败项的名字去查。

> 提示：因为程序清单要求管理员权限，运行 `--selftest` 时同样会弹一次 UAC，点「是」即可。自检只做本机检查，**不会真的动你的鼠标**。

### 8.2 联调验证：本机回环自检

想进一步确认网络层没问题，可以跑回环自检（主机/副机角色都在本机 127.0.0.1 上跑一遍，`=3000` 是超时毫秒数）：

```
LanMouseShare.exe --nettest=3000
```

同样看日志末尾是否出现：

```
NETTEST RESULT: PASS
```

这项**只在回环地址上跑，不装钩子、不动真实鼠标**，可以放心执行。

### 8.3 完整验收（从源码构建时）

如果你是从源码构建的，项目自带一条完整的自动验收脚本，一次跑完 32 项断言（自检 13 项 + 回环联调 19 项）：

```
powershell -ExecutionPolicy Bypass -File tools\smoke-test.ps1 -Configuration Release
```

对应的构建命令是：

```
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Configuration Release
```

产物在 `src\LanMouseShare.App\bin\Release\LanMouseShare.exe`。

从源码构建需要 .NET Framework 4.8 的**开发包**（Developer Pack）和 MSBuild（Visual Studio 或独立的 Build Tools）。

### 8.4 最后一步：两台机器连通

装完的判定标准是**副机能收到主机的输入**：

1. 主机、副机都启动程序（各自点掉 UAC）。
2. 两边填**同一个连接密钥**。
3. 副机填**主机 IP**（主机上点「复制本机 IP」按钮拿到的那个地址）。
4. 主机选「主机」角色，副机选「副机」角色。
5. 主机点「开始共享」，然后副机点「开始共享」。
6. 到主机「屏幕布局」页按实际摆放设好方向。
7. 推鼠标过边缘 —— 光标在副机上动了，部署成功。

装完跟用户交接时，把[使用手册](使用手册.md)一起给他。

## 9. 卸载

先看是哪种装法。

### 9.1 安装版（用 setup exe 装的）

最省事：**控制面板 → 程序和功能** → 找到 **LanMouseShare · 局域网键鼠共享** → 卸载。

也可以在命令行静默卸载（连配置和日志一起删）：

```
"%LOCALAPPDATA%\Programs\LanMouseShare\卸载 LanMouseShare.exe" --uninstall --purge --silent
```

卸载程序会自己：关掉正在运行的主程序 → 删掉桌面和开始菜单快捷方式 → 从「程序和功能」里移除登记 → 删掉程序目录（这个卸载程序自己就住在要被删的目录里，所以最后一步交给一个延时的 cmd 进程收尾，跑完不留空文件夹）。

**不加 `--purge` 会保留** `%LOCALAPPDATA%\LanMouseShare` 里的配置和日志（里面含你的连接密钥和主机 IP，介意就加 `--purge`）。

### 9.2 免安装版（zip 解压的）

1. **退出程序**：右键托盘图标 → **「退出(&X)」**。
   > 直接关主窗口只是最小化到托盘，进程还在跑，不算退出。
2. 确认进程真的没了：任务管理器里不应再有 `LanMouseShare.exe`。
3. **删除安装目录**（整个文件夹，例如 `C:\Tools\LanMouseShare`）。
4. **删除配置和日志**（可选，建议做）：直接删 `%LOCALAPPDATA%\LanMouseShare` 整个文件夹。

### 9.3 两种装法都建议顺手做的

- **删除防火墙规则**（如果你手工加过）：
  ```
  netsh advfirewall firewall delete rule name="LanMouseShare"
  ```
  > 用程序里的「放行防火墙」按钮建的规则，名字分别是 `LanMouseShare (TCP <端口>)` 和 `LanMouseShare (程序)`，也可以直接用这两条名字删。
- **删除随系统启动的项**（如果你配过）：
  - 启动文件夹方式：`Win + R` 输入 `shell:startup`，删掉里面的 LanMouseShare 快捷方式；
  - 任务计划程序方式：`taskschd.msc`，找到 `LanMouseShare` 任务删除。
- 如果杀软白名单里加过它，顺手清掉。

程序不装服务、不写系统目录；安装版只在 `HKCU` 下写一条卸载登记（卸载时自动删掉），配置和日志都在用户目录里，做完以上几步就是干净卸载。

## 10. 部署常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 双击没反应 / 报缺 .NET | 目标机器没装 .NET Framework 4.8。Win7 按第 2.2 节走三步 + 重启；Win10/11 用 2.1 节的注册表命令确认 |
| .NET 4.8 安装程序报签名无效 / 证书错误 | Win7 SP1 上的典型症状：**两个前置补丁没装或顺序装反**（先 KB4490628，再 KB4474419），且装完 4.8 要重启 |
| 启动时弹「此应用已被系统管理员阻止」 | 程序被 SmartScreen 或组策略拦了；确认安装包来源，必要时由管理员放行 |
| 启动了但共享不生效 | 先确认是不是**没有管理员权限**（UAC 弹窗不能取消）；再查杀软有没有拦全局钩子 |
| 副机连不上主机 | 主机没放行 24800 端口；两边密钥不一致；副机 IP 填错；两边都选了同一角色。用 `ping 主机IP` 先确认网络通 |
| 键盘不生效但鼠标正常 | 主机上「同时共享键盘」没勾（这是主机的开关，副机那边改不了） |
| 副机上有键一直按着（粘键） | 停一次再开一次共享；程序在停止共享和断线时都会补发「抬起」事件 |
| 想确认端口有没有被占 | 在主机上执行 `netstat -ano`，在输出里找 24800 |
